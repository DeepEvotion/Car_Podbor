# Автоподбор

Первый функциональный этап сайта по [исполнительному ТЗ](ТЗ_для_ИИ_агента_реализация_сайта.md). Интерфейс использует временные стили до получения макетов.

## Запуск

Сервер работает на Flask, данные хранятся в PostgreSQL. Для локального запуска нужен Python 3.12 или новее и PostgreSQL 14+.

Установите зависимости:

~~~powershell
python -m pip install -r requirements.txt
~~~

Создайте базу `carmatch` и задайте строку подключения:

~~~powershell
$env:DATABASE_URL = "postgresql://postgres:postgres@localhost:5432/carmatch"
~~~

Или запустите PostgreSQL через Docker:

~~~powershell
docker compose up -d postgres
$env:DATABASE_URL = "postgresql://postgres:postgres@localhost:5432/carmatch"
~~~

Таблицы создаются автоматически при старте, а каталог заполняется из `data/catalog.json` при первом запуске.

~~~powershell
python -m backend.app.main
~~~

Сайт открывается по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000). Кнопка «Посмотреть демо» открывает три готовых профиля с результатами и гаражами.

Для запуска через Flask CLI:

~~~powershell
flask --app 'backend.app.main:create_app()' run --host 127.0.0.1 --port 8000
~~~

## Подбор

Пользователь начинает с описания или типового сценария. Серверный разбор предлагает значения для анкеты. Их можно изменить или пропустить. Число мест, указанные границы бюджета и явно выбранные обязательные условия проверяются перед ранжированием. Если обязательная характеристика неизвестна, машина исключается. При пустой выдаче интерфейс показывает, на каких ограничениях отсеялось больше всего вариантов.

Сервер рассчитывает рациональное и эмоциональное совпадение и учитывает полноту данных. В режиме «Твой баланс» вес этих составляющих составляет 55%, 35% и 10%. Остальные режимы отдают приоритет рациональному или эмоциональному баллу. При равных баллах порядок стабилен. В выдачу попадает до пяти разных моделей.

Сервер подбирает до трёх дуэлей из допустимых машин. Пары и признаки не повторяются. Ответы меняют временный профиль по показанному признаку, а после каждой дуэли список кандидатов пересчитывается.

Гостевой гараж сохраняется в браузере. Для ссылки пользователь отмечает конкретные машины. Сервер публикует их идентификаторы и статусы, а ключ отзыва хранится в браузере создателя ссылки. Ссылка хранит снимок выбора и действует до отзыва или остановки процесса. Для открытия с другого устройства нужен общий адрес сервера.

## Файлы

- data/catalog.json — 24 реальные модели. Характеристики комплектаций требуют проверки, ценовые диапазоны используются для демонстрации, оценки стиля редакционные.
- backend/app/recommender.py — нормализация, фильтрация, ранжирование, объяснения, разбор текста и подбор пар.
- backend/app/main.py — Flask API и раздача frontend.
- backend/app/db.py — PostgreSQL-схема, seed каталога, фото-кэш и share-ссылки.
- frontend/index.html, frontend/app.js и frontend/styles.css — старт, анкета, дуэли, результаты, карточки, гараж и демо.
- backend/tests/ — тесты движка и HTTP API.

## Проверки

~~~powershell
python -m pytest -q
node --check frontend/app.js
~~~

Первой команде нужен pytest, второй — Node.js. Тесты проверяют строгие ограничения, неизвестные характеристики, воспроизводимость, дуэли, разбор текста, заполненные демо-гаражи, состав данных по ссылке и её отзыв.

## Состояние реализации

Текущий локальный прототип использует JavaScript, Flask и PostgreSQL. Миграции Alembic, серверная авторизация, друзья и Playwright остаются этапами реализации ТЗ. Приложение и рекомендации работают без внешнего AI.

## Персональные вопросы и фотографии

Нажмите «Начать подбор», опишите свою задачу и нажмите «Продолжить». При подключённом AI на первом шаге появится краткое резюме запроса. AI формулирует вопросы по темам анкеты и обновляет их порядок после первых трёх ответов. Подтверждённые ответы остаются в профиле. Без AI сайт уточняет детали по локальным правилам.

Для OpenAI-совместимого сервиса укажите в окружении сервера три переменные из .env.example:

- AI_CHAT_URL — полный HTTPS-адрес маршрута chat completions вашего провайдера.
- AI_MODEL — идентификатор модели у провайдера.
- AI_API_KEY — ключ доступа. Установите его в окружении, из которого запускаете Python. Не добавляйте значение в проект.

При включённом AI описание и ответы на пройденные темы передаются настроенному провайдеру для подготовки вопросов. Сайт получает фото с Wikimedia по мере появления карточек на экране. Ссылка под фото содержит автора и лицензию и открывает оригинал. Фото иллюстрируют модель, комплектация и поколение на снимке могут отличаться. При недоступности Wikimedia видна модель машины и текстовая заглушка.


Сервер также загружает эти переменные из локального файла .env в корне проекта. Скопируйте .env.example в .env, заполните значения и перезапустите сервер. Переменные окружения имеют приоритет. Маршрут /api/health показывает aiConfigured, а первый экран интервью показывает, использован ли AI или локальный подбор вопросов.

Фото выдаются через серверный `/api/photos/:carId`. Сервер ищет изображение модели в Wikimedia Commons, проверяет домен загрузки и наличие лицензии, кэширует результат и передаёт браузеру только разрешённый URL, подпись и источник.

Первичный текст пользователя передаётся в AI-адаптер вместе с допустимыми полями профиля. AI возвращает краткое понимание запроса и уникальный список вопросов, из которого формируется первый тест. Повторные вопросы удаляются по ключу. После трёх ответов вызывается `/api/ai/questions`, чтобы обновить дальнейшие вопросы с учётом уже выбранного. Если AI-провайдер не настроен или недоступен, локальный адаптер создаёт разные вопросы по найденным сигналам запроса и сохраняет источник теста в ответе API.
